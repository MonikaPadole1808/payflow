# Notification Module

## Milestone

06 - Notification Module

---

## Objective

Implement the Notification module for PayFlow Version 1.

The Notification module is responsible for recording notification events generated by successful business operations.

Version 1 stores notification history only.

Actual email, SMS, push notification delivery, Kafka integration, and schedulers are intentionally excluded.

## Functional Requirements

### Notification Creation

Notifications are created internally after successful business events.

Version 1 Events

- User Registration
- Wallet Deposit
- Wallet Withdrawal
- Payment Transfer Sent
- Payment Transfer Received

No public API shall create notifications.

---

### Notification History

Authenticated users can retrieve their own notifications.

Notifications are returned newest first.

---

### Notification Details

Authenticated users can retrieve one notification owned by them.

---

### Mark as Read

Authenticated users may mark one notification as read.

Only the notification owner may perform this operation.

## Business Rules

Notifications are created only after successful business operations.

Users can access only their own notifications.

Notifications are never deleted.

Version 1 supports only READ and UNREAD states.

---

## API Endpoints

/api/v1/notifications

---

/api/v1/notifications/{id}

Return notification details.

---

PATCH

/api/v1/notifications/{id}/read

Mark notification as READ.

---

No notification creation endpoint.
